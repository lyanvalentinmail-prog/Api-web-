      Cómo funciona este proyecto
      
          Transparencia
        
      
        
      
          
      
            
      Endpoints propios
      
            
      
              Se ejecutan en este servidor Node.js con Express: no dependen de terceros, no necesitan clave y responden aunque
              no haya Internet. Código y definiciones incluidos en el repositorio.
            
      
            
      Endpoints externos
      
            
      
              Son un proxy de solo lectura hacia APIs públicas que no piden clave. La URL se construye en el
              servidor a partir de una lista fija de proveedores y de parámetros validados (no se puede usar como proxy
              abierto). Cada proveedor tiene sus propios límites, indicados en su documentación dentro de la web.
            
      
          
      
          
      
            
      Límites de uso

      Sin cuentas ni claves
      
            
      
              No hay registro, login, correo ni API key. Tampoco se usan cookies ni se pide ningún dato personal: el
              limitador de peticiones sólo cuenta peticiones por IP y la usa exclusivamente para evitar abusos.
            
      
          
      
        
      

        
      Cómo se comporta según dónde lo despliegues
      
        
      
          
      
            
              
      PlataformaModelo de ejecuciónQué cambia
      
                  
            
              
      
                Local, Docker, Render, Railway, Fly.io o VPS
                Servidor Node permanente (server.js)
                
                  Todos los endpoints propios y los externos funcionan igual que aquí. La caché (45 s de estado, cachés de
                  proveedores) y el limitador de peticiones son por proceso y se mantienen entre peticiones.
                
              
      
              
      
                Vercel (u otro entorno serverless)
                Función por petición, sin proceso permanente
                
                  El CRUD de ejemplo se guarda en memoria de la instancia: puede reiniciarse o alternar entre instancias, así
                  que trátalo como datos volátiles. Las cachés duran lo que vive la instancia, por lo que se hacen más
                  consultas reales a los proveedores externos (conviene no abusar de /api/status). Los contadores
                  X-RateLimit-* son orientativos. Todo lo demás se comporta igual.
                
              
      
                  
          
      
        
      
        
      
          Instrucciones concretas para cada plataforma en el README (sección «Despliegue»). Este proyecto
          no está publicado en ninguna URL: si lo estás viendo en local, se ejecuta sólo en este equipo.
